bitcoin watcher

a live kraken order book on the desktop. c# and avalonia, one websocket, ten price levels a side, redrawn ten times a second.

c# / .net 10 avalonia websocket channels github ↗

what it is

a desktop window showing kraken's btc/usd book in real time. bids down the left, asks down the right, ten levels on each side, and a row flashes green or red for a third of a second when its size moves. thats the whole product. about 850 lines behind it.

the part i was actually curious about was how little i could lean on. avalonia draws the window and thats the extent of the framework -- no reactiveui, no mvvm toolkit, no di container, INotifyPropertyChanged written out by hand. the book is two dictionaries and everything between the socket and the screen is System.Threading.Channels. a market data feed is a producer/consumer problem wearing a ui, and i wanted the seams where one hands off to the other to stay visible instead of disappearing into a library.

how it flows

ClientWebSocketframes in, reassembled until EndOfMessage
KrakenParseutf8 span to a concrete record
inbox channelunbounded, single writer
OrderBookStreamchannel to .net events
ViewModelqueue, drained at 10hz

five hops, one direction, and every boundary is either a channel or an event. nothing reaches back upstream. the socket does not know a window exists and the viewmodel does not know what a websocket is -- the stream in the middle is the only thing holding both ideas at once, and it is sixty lines.

KrakenParse does not deserialize into a polymorphic base. it parses the document, looks for a method property to spot a subscription ack or a channel property to spot data, and then deserializes the whole root into the concrete record. heartbeat and status frames come back null and never make it onto the channel at all. its a sniff rather than a schema, which i would not do against a big api, but the v2 book feed is four message shapes and pretending otherwise would have been ceremony.

the socket

ProcessAsync is a reconnect loop with a socket inside it, not a socket with reconnect bolted onto the side. each pass builds a fresh ClientWebSocket, connects, subscribes, and starts two loops over a linked cancellation token -- one draining the outbox onto the wire, one reading frames off it. Task.WhenAny means whichever one dies first cancels the token out from under the other, and the WhenAll after it waits for that other one to actually finish before the loop comes back around. no orphaned reader still writing into a socket thats already gone.

a fault just falls out the bottom into the backoff: 500ms doubling up to a 30 second ceiling, multiplied by a random factor between 0.5 and 1.5. the jitter is there because the failure that knocks you off is usually the exchange, and every client it knocked off is holding the same doubling schedule you are.

the read loop rents 16k out of ArrayPool and accumulates into an ArrayBufferWriter until EndOfMessage, since a full depth snapshot does not arrive in one receive. parsing runs straight off the accumulated ReadOnlySpan<byte> with a Utf8JsonReader -- no intermediate string, nothing copied to be thrown away. a frame that fails to parse gets logged and dropped rather than thrown, because the read loop is the only thing keeping the window alive and one malformed byte from a venue i dont control should not be able to end it.

the outbox is bounded at 64 with DropOldest. subscribe messages are small and rare, so if that ever backs up something has gone badly wrong somewhere else and the newest message is the one worth keeping.

keeping the ui honest

the socket can deliver several updates inside one frame and several frames inside one animation interval. binding straight to it means the ui thread doing layout work that gets overwritten before a human could have seen it. so the viewmodel does not render on arrival -- updates land in a ConcurrentQueue and a DispatcherTimer drains all of it every 100ms and redraws once. bursts collapse into one redraw for free.

kraken sends deltas and a level with quantity zero means remove it. apply that to the two dictionaries, sort, take the top ten a side, then hand the result to Reconcile. reconcile is the piece i actually care about: it matches incoming levels against the row objects already on screen by price and reuses them instead of allocating new ones. a row that survives keeps its flash timer, so a price level thats been ticking for thirty seconds doesnt restart its animation every hundred milliseconds, and the collection only gets cleared and rebuilt when the top ten genuinely changed.

the flash is versioned for the same reason. every Update bumps a counter and schedules a clear 350ms out, and that clear only fires if its version is still the newest. skip that and two updates 50ms apart leave the row dark 300ms early -- which reads on screen as the book going quiet exactly when it got busy, the opposite of what you want the animation to tell you.

whats not finished

theres a second path in the repo that the app never calls. Observers/KrakenObserver.cs signs a rest request with hmac-sha512 to get a websocket token, opens its own connection, and builds the book out of TracedConcurrentDictionary -- a dictionary that mirrors every add, update and delete into a bounded channel with a sequence number and a Stopwatch timestamp. thats the version i want, because it gives you a mutation log for free: the flash animation stops being a diff between two renders and becomes a read of what the book actually did. but App.axaml.cs starts KrakenOrderBookStream and nothing else, so today its dead code with a good idea sitting in it.

its also wrong as written. the update branch calls TryAdd, which returns false and does nothing when the key is already there, so a level that changes size never changes and a level that goes to zero never leaves. the snapshot populates correctly and then every delta after it is a no-op. the path in Services/ handles deltas properly, which is the only reason the window looks right.

two more gaps worth naming. BookData parses kraken's crc32 checksum and nothing verifies it -- that checksum is the real correctness check for a book you are maintaining from deltas, and without it you discover youve drifted by staring at the screen and feeling like something is off. and the viewmodel already computes BestBid, BestAsk, Spread and a connection Status that MainWindow.axaml never binds to, so the window cannot tell you whether its live or quietly disconnected. the reconnect loop is the piece of this i trust most and the ui gives you no way to watch it work.

sniffs the json root and picks a record. drops what it doesnt know.

channel to events. the only file that knows about both halves.

ViewModels/OrderBookViewModel.cs

book state, 10hz coalescing, row reconcile and the flash timers.

MainWindow.axaml

two cards, bids and asks, monospace and right aligned sizes.

Objects/TracedConcurrentDictionary.cs

a dictionary that emits a sequenced mutation log. built, not wired in.

Observers/Implementations/KrakenObserver.cs

the authenticated path. signs for a token, then never gets started.

the source

using System.Buffers;
using System.Net.WebSockets;
using System.Text.Json;
using System.Threading.Channels;
using Microsoft.Extensions.Logging;
using WS.Messages;

namespace WS;
///
/// Kraken WebSocket
/// outbox / inbox channels, 
/// 
public sealed class KrakenWebSocket : IAsyncDisposable
{
    private readonly ILogger _logger;
    private readonly Channel<string> _outbox;
    private readonly Channel<object> _inbox;
    public ChannelReader<object> Messages { get; }
    private ClientWebSocket? _ws;
    private DateTimeOffset _lastFrame;
    private readonly Uri _publicDataWSPath = new("wss://ws.kraken.com/v2");

    public KrakenWebSocket(ILogger logger) {
        _logger = logger;
        _outbox = Channel.CreateBounded<string>(new BoundedChannelOptions(64) 
        { 
            SingleReader = true,
            FullMode = BoundedChannelFullMode.DropOldest
        });
        _inbox = Channel.CreateUnbounded<object>(new UnboundedChannelOptions{ SingleWriter = true });
        Messages = _inbox.Reader;
        _lastFrame = DateTimeOffset.UtcNow;
    }

    public ValueTask SubscribeAsync(IReadOnlyList<string> symbols, int depth, CancellationToken ct) {
        var req = new SubscribeRequest(new BookSubscribeParams(symbols, depth));
        var msg = JsonSerializer.Serialize(req, KrakenJson.Options);
        return _outbox.Writer.WriteAsync(msg, ct);
    }

    public async Task ReadAsync(ClientWebSocket ws, CancellationToken ct) {
        var buff = ArrayPool<byte>.Shared.Rent(16 * 1024);
        var accum = new ArrayBufferWriter<byte>(16 * 1024);
        try
        {
            while (!ct.IsCancellationRequested && ws.State == WebSocketState.Open) {
                ValueWebSocketReceiveResult result;
                accum.Clear();
                do {
                    result = await ws.ReceiveAsync(buff.AsMemory(), ct);
                    if (result.MessageType == WebSocketMessageType.Close) {
                        _logger.LogWarning("Warning: connection closed.");
                        return;
                    }

                    accum.Write(buff.AsSpan(0, result.Count));
                } while (!result.EndOfMessage);
                _lastFrame = DateTime.UtcNow;

                try
                {
                    if (KrakenParse.Parse(accum.WrittenSpan) is { } msg)
                        await _inbox.Writer.WriteAsync(msg, ct);
                } 
                catch (JsonException ex) {
                    _logger.LogWarning(ex, "Unparsable frame, dropped.");
                }
            }
        }
        finally { ArrayPool<byte>.Shared.Return(buff, true); }
    }
    private async Task WriteLoopAsync(ClientWebSocket ws, CancellationToken ct)
    {
        await foreach (var json in _outbox.Reader.ReadAllAsync(ct))
        {
            await ws.SendAsync(System.Text.Encoding.UTF8.GetBytes(json),
                               WebSocketMessageType.Text, endOfMessage: true, ct);
        }
    }

    public async Task ProcessAsync(IReadOnlyList<string> symbols, CancellationToken ct) {
        int attempt = 0;
        while (!ct.IsCancellationRequested) {
            try {
                // create a new web socket connection 
                using var ws = new ClientWebSocket();
                await ws.ConnectAsync(_publicDataWSPath, ct);
                _ws = ws;
                _lastFrame = DateTime.UtcNow;
                attempt = 0;

                _logger.LogInformation("websocket connected");
                _logger.LogInformation($"subscribing with symbols {string.Join(',', symbols.Select(s => s))}");
                await SubscribeAsync(symbols, 10, ct);

                using var linked = CancellationTokenSource.CreateLinkedTokenSource(ct);
                var reader = ReadAsync(ws, linked.Token);
                var writer = WriteLoopAsync(ws, linked.Token);
 
                // whichever faults first tears the others down. no orphaned loops.
                await Task.WhenAny(reader, writer);
                linked.Cancel();
                await Task.WhenAll(
                    reader.ContinueWith(_ => { }, TaskScheduler.Default),
                    writer.ContinueWith(_ => { }, TaskScheduler.Default));

            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                return;
            }
            catch (Exception ex)
            {
                _logger.LogWarning(ex, "socket faulted");
            }

            var delay = TimeSpan.FromMilliseconds(
                Math.Min(30_000, 500 * Math.Pow(2, attempt++)) * (0.5 + Random.Shared.NextDouble()));
            _logger.LogInformation($"reconnecting in {delay}");

            await Task.Delay(delay, ct);
        }
    }

    public async ValueTask DisposeAsync() {
        _outbox.Writer.TryComplete();
        if (_ws?.State == WebSocketState.Open )
        {
            using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(2));
            try { await _ws.CloseAsync(WebSocketCloseStatus.NormalClosure, "bye", cts.Token); }
            catch { /* already gone; nothing to salvage */ }
        }
        _ws?.Dispose();
    }
}
